# 03.07.08 Natural Key

## Learning Objectives

After completing this lesson, you will be able to:

- Understand what a Natural Key is
- Learn how Natural Keys originate from business data
- Differentiate Natural Keys from Surrogate Keys
- Identify good and bad Natural Keys
- Understand when Natural Keys are appropriate
- Follow best practices used in modern database design

---

# Introduction

Imagine you're designing a Passport Management System.

Every citizen has a unique passport number.

| PassportNo | Name | Country |
|------------|------|----------|
| N1234567 | John | India |
| N2345678 | Alice | India |
| N3456789 | David | India |

The passport number already uniquely identifies every citizen.

There is no need to generate another identifier.

The existing business value itself can be used as the Primary Key.

This is called a **Natural Key**.

---

# What is a Natural Key?

A **Natural Key** is a **real-world business value** that naturally identifies a record uniquely.

Unlike a Surrogate Key, it is **not generated by the database**.

Examples include:

- Passport Number
- ISBN
- Vehicle VIN
- Aadhaar Number
- PAN Number
- GSTIN
- Employee Code (if permanent)
- Student Roll Number (if permanent)

---

# Simple Definition

```
Real Business Data

↓

Already Unique

↓

Used as Primary Key

↓

Natural Key
```

---

# Characteristics

A Natural Key:

- Has business meaning
- Already exists before the database is created
- Is unique
- May serve as a Primary Key
- Is meaningful to users
- Should remain stable over time

# SQL Example

```sql
CREATE TABLE Books
(
    ISBN CHAR(13) PRIMARY KEY,
    Title VARCHAR(200),
    Author VARCHAR(100),
    Price DECIMAL(10,2)
);
```

---

## Explanation

`ISBN`

- Already exists
- Is globally unique
- Has business meaning

Therefore, it is a Natural Key.

---

# Another Example

```sql
CREATE TABLE Passports
(
    PassportNo VARCHAR(20) PRIMARY KEY,
    HolderName VARCHAR(100),
    Country VARCHAR(50)
);
```

Every passport already has a unique passport number.

No additional ID is required.

# Natural Key vs Surrogate Key

| Natural Key | Surrogate Key |
|--------------|---------------|
| Real business value | Artificial value |
| Has business meaning | No business meaning |
| Already exists | Generated by database |
| May change | Never changes |
| Meaningful to users | Meaningless to users |
| May become Primary Key | Usually becomes Primary Key |

---

# Natural Key vs Primary Key

| Natural Key | Primary Key |
|-------------|-------------|
| One type of key | Database constraint |
| May become Primary Key | Can be Natural or Surrogate |
| Business identifier | Official table identifier |

A Primary Key can be either:

- Natural Key
- Surrogate Key

# Industry Practice

## Small Applications

Natural Keys are often sufficient.

Examples

- School Management System
- Library Management System
- Small Inventory System
- College Projects
- Personal Applications

---

## Enterprise Applications

Surrogate Keys are generally preferred.

Business identifiers are stored using `UNIQUE` constraints.

Examples

- ERP
- CRM
- HRMS
- Banking
- Healthcare
- Insurance
- E-Commerce
- SaaS Platforms

---

# Hybrid Design (Most Common)

Modern applications often use **both** Natural and Surrogate Keys.

Example

```
CustomerID

↓

Surrogate Key

+

Email

↓

Natural Business Identifier
```

Database Design

| CustomerID | Email |
|------------|-------|
|101|john@gmail.com|
|102|alice@gmail.com|

- `CustomerID` → Primary Key
- `Email` → UNIQUE Constraint

This provides both stability and business validation.

---

# Advantages

- Easy for users to understand
- No additional ID generation required
- Represents real business data
- Reduces unnecessary columns in small databases
- Useful when the identifier is guaranteed to remain stable

---

# Disadvantages

- Business values may change
- Longer indexes
- Larger Foreign Keys
- More expensive joins
- Updating keys affects related tables
- Some Natural Keys expose sensitive business information

---

# Best Practices

- Use Natural Keys only if they are truly permanent.
- Avoid Natural Keys that users can edit.
- Use `UNIQUE` constraints for important business identifiers.
- Prefer Surrogate Keys for enterprise systems.
- Carefully evaluate long-term stability before choosing a Natural Key.

---

# Common Mistakes

❌ Using Email as a Primary Key

Users change email addresses.

---

❌ Using Mobile Number

Phone numbers change frequently.

---

❌ Using Person Name

Names are not guaranteed to be unique.

---

❌ Assuming every business value is a good Natural Key

Only stable and unique values should be considered.

---

# 💡 Did You Know?

Many developers believe Natural Keys are "old-fashioned."

That's not true.

Natural Keys are still widely used when the identifier is:

- Globally unique
- Permanent
- Controlled by an external authority

For example:

- ISBN for books
- VIN for vehicles
- Passport Number
- ISO Country Codes
- Currency Codes (`USD`, `GBP`, `INR`)
- Airport Codes (`LHR`, `JFK`, `DEL`)

Even systems that use Surrogate Keys internally often enforce these values with `UNIQUE` constraints because they remain important business identifiers.

# Interview Questions

### What is a Natural Key?

A Natural Key is a real-world business value that uniquely identifies a record.

---

### Is a Natural Key generated by the database?

No.

It already exists before the database is created.

---

### Can a Natural Key become a Primary Key?

Yes.

If it is unique, stable, and never changes.

---

### Why do enterprise systems often avoid Natural Keys as Primary Keys?

Because business values may change, increasing maintenance and affecting related tables.

---

### Give examples of good Natural Keys.

- ISBN
- Passport Number
- Vehicle VIN
- PAN Number
- GSTIN

---

### What is the biggest difference between a Natural Key and a Surrogate Key?

A Natural Key comes from real-world business data.

A Surrogate Key is generated by the database and has no business meaning.
